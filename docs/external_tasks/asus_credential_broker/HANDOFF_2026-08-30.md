## Objective

Restore autonomous, safe administrative access from Skeleton Home Edge to the registered ASUS RT-AC51U (`asus_router_modem`) without exposing plaintext credentials and without changing router/network configuration.

## Missing canonical capability

Current Skeleton main checkout contains no canonical Bitwarden integration / SecretReference / credential broker implementation for this path. The local ASUS adapter cannot safely retrieve an opaque credential reference and establish a session.

The required architecture is:

`registered device_id -> opaque secret reference -> local credential/action broker -> bounded ASUS login/session refresh -> cookie with 0600 permissions -> protected read-only verification`

The assistant/tool boundary must never receive the password value.

## Security requirements

1. Never print, log, commit, return, or persist the plaintext password outside the secret provider/runtime memory.
2. Never put the password in MemoryGate, Device Registry, GitHub, audit receipts, argv, shell history, environment dumps, or unencrypted temp files.
3. Prefer an opaque `SecretReference`/secret key stored in the device registry.
4. Secret resolution and device login must occur locally at the trusted execution boundary on Home Edge.
5. Credential value must not be returned to caller; return only bounded status such as `session=ready|rejected|locked|unreachable`.
6. Use a dedicated cookie jar under Home Edge state, mode 0600.
7. Rate-limit authentication attempts; on an explicit bad-credential/lock signal, stop rather than retry.
8. This task is access repair only. Do not mutate WAN, DHCP, DNS, firewall, Wi-Fi, modem, UPnP, firmware, or any other network setting.
9. Preserve live internet connectivity.
10. All execution must remain inside the existing Skeleton Home Edge executor/ActionGate model; do not create a second privileged executor.

## Proposed minimal implementation

Implement a canonical Home Edge credential-backed device session operation, with an ASUS-specific provider initially.

Suggested contract conceptually:

- input: `device_id`, `operation_id/session_refresh`, opaque `secret_ref`
- executor resolves the secret locally
- provider constructs the exact ASUS login payload in process memory
- provider performs one bounded login attempt
- provider validates success by reading a protected endpoint, not merely HTTP 200/302
- provider persists only the resulting cookie/session material
- output contains no credential material

A generic interface is preferred over hard-coding Bitwarden calls in `/home/oleksii/.local/bin/skeleton-asus`, so other registered devices can reuse the same secret boundary later.

## Acceptance criteria

1. Unit tests prove secret values never appear in command argv, structured result, logs, exceptions, or audit output.
2. Wrong-secret test performs at most one login attempt and reports `rejected`/`locked` without retry storm.
3. Live runtime can resolve `router/asus_router_modem/admin` locally without exposing its value to the caller.
4. `skeleton-asus doctor` (or canonical replacement) can refresh an expired session autonomously.
5. Independent live verification successfully reads protected read-only ASUS data such as product ID / firmware / WAN state through `appGet.cgi`.
6. Router configuration is byte-for-byte/unobservably unchanged by the access-repair operation; no apply endpoint is invoked.
7. Internet route remains healthy after verification.
8. Register the confirmed session-refresh operation in the device operation registry with preconditions, verification, retry policy, and audit metadata.
